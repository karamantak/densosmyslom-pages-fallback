# A20.1 — независимые публикации «День со смыслом»
Текущий статус: **готовы черновики/отправщики; автопубликации ещё не запущены**. Работает независимо от Beget и его БД.

## Запуск без сети
- `node prepare.mjs --date 2026-11-06 --days 7`: создать JSON-очередь на 7 дней. Существующие отредактированные очереди сохраняются.
- `node prepare.mjs --date 2026-11-06 --days 7 --force`: сознательно заново создать очереди (перезапишет предыдущие; использовать только при необходимости).
- `node deliver.mjs --date 2026-11-06 --platform all --now 2026-11-06T15:00:00Z`: БЕЗОПАСНАЯ имитация отправки.
- `node --test a20-social.test.mjs`: автономные тесты.

## Формат
- 08:00 МСК: все основные события дня (при нехватке лимита текста несколько сообщений).
- 10:00 МСК: видео-задание `awaiting_video`, **ничего не отправляется без готового ролика**.
- 13:00 МСК: отдельное событие, 18:00 МСК: другая запись с историей.
- Дополнительная база A18 (UNVERIFIED) исключена; не выдавать её за проверенную.
- Защитная задержка: пропущенные записи старше 12 часов не публикуются пачкой после аварии.

## Подключение доступа — только секретами среды, никогда не писать в код/чат/GitHub
- Telegram: `A20_TG_TOKEN`, `A20_TG_CHAT_ID` (бот администратор канала).
- MAX: `A20_MAX_TOKEN`, `A20_MAX_CHAT_ID` (бот в канале, платформа `platform-api2.max.ru`).
- VK: `A20_VK_TOKEN`, `A20_VK_GROUP_ID` (разрешение публикации в сообщество).
- ОК: `A20_OK_TOKEN`, `A20_OK_APP_KEY`, `A20_OK_SESSION_SECRET`, `A20_OK_GROUP_ID` (GROUP_CONTENT, подпись по API).
- Отправка ВСЕГДА требует `--live` **и** `A20_ENABLE_PUBLISH=yes`. Запуск без них ничего не отправляет.

## Перед включением production
1. Провести тест в приватном чате/сообществе, проверить каждую API-роль и оформление.
2. Реализовать общий атомарный журнал отправок в независимом облаке. Сейчас журнал локальный: **нельзя включать 2 параллельных активных издателя**, иначе возможны дубли.
3. Подключить создание и выгрузку изображений/видео; текущая очередь — ТЕКСТ, не законченный медиапак.
4. Подключить GitHub Actions/Yandex расписание и мониторинг. На ноутбук для ежедневных публикаций не полагаться.
5. Не хранить токены внутри `queue`, `delivery.json` или архива.
